# Leona Quantum News

世界の量子ニュースを調査し、日本語記事と画像を保存するニュースメディアです。ニュース用の画面は `apps/news`、DB操作は既存APIの `repos/news.py`、生成と定期実行は既存Workerが担当します。

## 画面を起動する

Node.js 22以上。画面側に追加ライブラリはありません。

```sh
cd apps/news
npm run dev
```

http://127.0.0.1:3100 を開きます。既存の `.env` は保持されています。新しい設定項目は `.env.example` を参照して追加してください。ファイル全体の上書きは不要です。

`LEONA_NEWS_MODE` は次の3種類です。

| モード | 表示内容 |
|---|---|
| `preview` | デザイン確認用のサンプル記事。API接続不要 |
| `editor` | 実際の下書きと編集画面。localhost限定、既存の管理者認証が必要 |
| `published` | APIが公開済みとして返す実記事だけ。サンプルへのフォールバックなし |

APIキーはWorkerが使用します。画面側にキーを設定しただけでは、収集は始まりません。

## 実装した処理

1. 管理者の収集依頼、またはWorkerの定期実行から、既存のジョブキューに登録。
2. OpenAI Web検索で候補を探し、既に記事化したものを避けて一件を調査。arXiv補助検索は設定で追加可能。
3. 構造化した日本語記事を作成。段落ごとの出典、一次情報、出来事の日付、画像の題材を保持。
4. 別の検索で記事全体を検証し、出典を確認できない場合は保留。
5. 記事・検証結果・画像をDBへ保存。自動公開を有効にしていなければ下書きで停止。
6. 編集画面で本文・出典・画像を確認して公開。本文修正時は検証と画像を再設定。取り下げと訂正記録にも対応。

写真は、利用条件を確認した画像を編集画面から登録します。出典URL、利用条件URL、クレジット、確認内容が必須です。インターネット上の画像を無条件にダウンロードする処理はありません。生成画像は概念イラストとして明記します。

## 保存と制御

- `news_batches`：依頼、利用回数、途中結果、処理状態。再開時に保存済みの段階を飛ばします。
- `news_articles`：本文、出典、検証結果、公開状態、訂正前の本文、公開操作の記録。
- `news_assets`：正規化したWebP画像と出典・許諾情報。1枚600 KBまで。記事との対応をDB制約で保証します。
- API・WorkerだけがDBに接続。全リポジトリ操作でworkspaceを指定し、RLSも適用します。
- 依頼ごとの冪等キー、一次情報URLの重複制約、実行権の確認、1日の依頼数と依頼ごとのAPI呼び出し上限を設けています。
- 公開時には検証結果、本文のダイジェスト、画像のダイジェストを照合します。

これはAPIの呼び出し回数による上限です。ドル建ての請求上限を保証する仕組みではありません。モデル料金と利用量を確認して、運用上限を決めてください。

## 本番接続と運用

詳細は [RUNBOOK.md](RUNBOOK.md) を参照してください。API・Workerの設定、DB移行、編集者の認証、Cloud Runへのデプロイ計画、DNS接続、監視項目を記載しています。

本番は、このフォルダの既存の `Dockerfile` からビルドしたイメージをCloud Runにデプロイする計画です（未デプロイ。手順はRUNBOOK.mdを参照）。公開・定期収集の設定はルートの `infra/news.json` で管理し、既存のAPI・Workerデプロイが反映します。初期値は無効です。

コンテナで動かす場合は、このフォルダをビルドコンテキストにします。

```sh
docker build -t leona-news:local apps/news
```

上のコマンドはリポジトリのルートで実行します。コンテナには `.env` をコピーしません。既存のLeona本体と独立して配置できます。

## 検証

```sh
npm run build
npm test
```

Python側の統合テストは、専用の使い捨てPostgreSQLへ移行を適用してから実行します。手順はRUNBOOKにあります。

実際のOpenAI APIへの有料リクエストはこの実装作業では実行していません。SDKは模擬HTTPレスポンスで検証し、DB・API・画面の接続は実際のPostgreSQLで確認しています。公開前に、使用するOpenAIプロジェクトでのモデル利用可否と実記事の品質を確認する必要があります。
