# Pip fallback for the `notebooks` extra. Install alongside requirements.txt:
#
#   python -m pip install -r requirements.txt -r requirements-notebooks.txt
#
# Same rule as requirements.txt: the floors are what uv.lock actually resolves,
# because a resolver is free to take the floor and whatever this file permits is
# an environment a learner can end up in. `nbconvert` and `idna` are named even
# though nothing here asks for them directly — jupyterlab pulls both, and with
# only `jupyterlab>=4.0` stated the fallback resolved to nbconvert 7.17.1's
# predecessor 7.9.2, carrying a CVSS 8.5 advisory plus two more. Naming a
# transitive dependency is the only way a reader can audit it.
#
# The same rule bit jupyterlab itself on 2026-09-17. The floor read `>=4.6`
# while uv.lock resolved 4.6.3, and two advisories published that day —
# GHSA-gx64-gj6p-pc4c (CVSS 7.5) and GHSA-pppj-hq3g-57pj (CVSS 8.6), both XSS,
# both patched in 4.6.2 — cover exactly 4.6.0 and 4.6.1. Nobody was running a
# vulnerable version; the FLOOR permitted one, which is what this file is for
# and what the scanner reads. Raised to what the lock resolves.
jupyterlab>=4.6.3
ipykernel>=7.3
nbformat>=5.11
nbclient>=0.11
nbconvert>=7.17.1
idna>=3.19
