# Phase 10 S7-S8 academic and systems audit

Date: 2026-08-03 JST

Compared with: `origin/dev` at `89ce101`  
Scope: Phase 10 S7 execution-policy/qualification contracts, S8 executor-probe

## Conclusion

The current branch remains fail-closed and does not authorize public execution
or scientific publication. Two pre-approval integrity defects were found and
fixed:

1. S7 previously accepted repository coordinates and retrieval digests as
   independent scalar arguments. A caller could therefore splice source
   identity from one acquisition into the normalized/static candidate from
   another acquisition while still producing a structurally valid unqualified
   candidate.
2. The client-selection contract accepted the same `phase10-qic` namespace used
   by unapproved candidate identities. A trusted registry was still required,
   but the shared namespace made candidate and approved identities too easy to
   confuse in a future deployment.

S7 now derives source identity from the actual acquisition result, validates the
complete acquisition → quarantine → normalization → static-candidate chain,
and rejects file, locator, workspace, or digest mismatches. Candidate IDs remain
`phase10-qic:<sha256>` while client-selectable, authority-issued IDs must use
`phase10-qi:<sha256>`.

## Academic audit

### Preserved scientific boundaries

- H₂ energy, fidelity, CNOT, depth, and parameter observations remain private
  research candidates, not public results.
- `owner_waived` remains distinct from independent human scientific review.
- Qiskit/PennyLane agreement proves parity only for the frozen H₂ protocol and
  exact runtime bindings that were executed. It does not establish general
  framework equivalence.
- CNOT/depth values use the documented canonical ansatz-only decomposition
  protocol. They exclude reference-state preparation, measurement, target
  hardware optimization, and routing, so they must not be presented as physical
  device resource costs.
- Phase 10 S7/S8 records contain policy and probe candidates only. They do not
  prove equivalence to an external paper, scientific correctness of external
  code, or performance superiority.

### Academic defect fixed

The old S7 source binding could associate a valid repository/commit label with
the bytes and static candidate of another source. That would make provenance
claims misleading even if execution stayed private. The strict parent-chain
builder now derives repository identity and checks exact ordered source-file
metadata and opaque locators at every stage.

### Remaining academic blockers

- S9 independent result verification is not implemented.
- No hostile external-source result has been scientifically validated.
- No independent human review exists; the recorded owner waiver is transparent
  but is not substitute evidence.
- Phase 10 cannot support publication, reproducibility, or superiority claims
  until exact inputs, results, verifier observations, and release decisions are
  immutably bound and independently inspected.

## Systems-engineering audit

### Controls confirmed

- All S7/S8 contracts are pure and perform no network, database, subprocess, or
  credential operation.
- Runtime images are represented only by lowercase SHA-256 OCI index digests;
  tags such as `latest` are rejected.
- Platform, launcher surface, file roots, deny-all network policy,
  no-credential policy, deterministic controls, failure taxonomy, and retry
  semantics are fixed by the contract.
- Every policy, qualification candidate, and passing probe observation remains
  explicitly `unqualified`.
- Unknown fields, relaxed policy surfaces, changed digests, missing/reordered
  probes, generic failure codes, and self-declared qualification fail closed.
- Repository-layer import boundaries and the raw-query guard remain intact.

### Systems defects fixed

| Severity | Defect | Resolution |
| --- | --- | --- |
| High | Cross-source/cross-workspace evidence splicing was possible at the S7 builder boundary. | Require actual S2/S3/S5/S6 parent objects and verify all parent digests, workspace, ordered files, and opaque locators. |
| High | An unapproved `phase10-qic` candidate could occupy the client selection field intended for an approved identity. | Reserve `phase10-qic` for candidates; accept only separate `phase10-qi` authority identities in client selection. |
| Medium | The Phase 10 master-plan status still said all implementation was blocked after S0-S8 offline contracts had landed. | State that S0-S8 offline contracts exist while live external execution remains blocked. |

### Remaining security and operations blockers

- No approval authority currently issues `phase10-qi` identities or binds them
  to candidate identity, live probe observation, and immutable approval evidence.
- The resolver intentionally trusts a deployment-owned registry. Passing a
  client-owned mapping would be unsafe; no production caller exists yet.
- S8 evidence digests are structural references, not cryptographic attestations
  from a live isolated executor. A caller can construct an unqualified
  observation with arbitrary evidence hashes; it cannot promote that record.
- Exact resource-limit values are positive and bounded as integers but have not
  been safety-qualified for a deployment class.
- Dedicated fetcher identity, private quarantine persistence, hardened executor,
  live deny-all egress proof, hostile repository corpus, private canary, and
  owner go/no-go are still pending.
- 404 tests were skipped in the full local suite because their optional service,
  platform, or integration prerequisites were not present. These skips are not
  counted as passing evidence and must be covered by their designated CI/live
  qualification jobs.
