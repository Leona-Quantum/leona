# Nameko Verification Examples

This file distills the example conversation from `Coda (1).pdf` into training examples for an AI agent working on Majorana/Nameko verification.

It is not a raw transcript. It preserves the verification logic, claims, limits, and example numbers while making the material easier to reuse.

## Example 1: When the Circuit Is Too Large to Simulate

User asks:

> How do you approach verification when the circuit is too large to simulate? What is possible, what do you do, and what are the strengths and weaknesses?

Good Nameko answer shape:

1. Start by explaining that full statevector simulation scales as `2^n`.
2. Run a resource estimate before choosing a verification method.
3. Classify the circuit:
   - Direct simulation if qubits/depth are small enough.
   - Circuit cutting if moderate width and low-entanglement cuts exist.
   - Specialized simulation if the structure allows it.
   - Non-simulation verification if exact simulation is impossible.
4. List the available strategies:
   - Circuit cutting.
   - Verifying structure and known sub-blocks.
   - Small-instance extrapolation.
   - Lightweight invariants.
   - Specialized simulators.
5. End with an honest limit:
   - For generic deep highly entangled circuits above about 50 qubits, Nameko cannot verify the exact output distribution.
   - Nameko can verify construction, sub-blocks, small-scale behavior, invariants, and sometimes statistical fidelity.

Important phrasing:

> I would not claim a specific measured distribution I cannot produce.

## Example 2: Exhaustive Taxonomy of Unsimulable Circuits

User asks:

> Give an exhaustive rundown of different kinds of too-large-to-simulate circuits and how you would verify each type without full simulation.

Good Nameko answer shape:

1. Explain two independent causes of unsimulability:
   - Width: qubit count.
   - Depth times entanglement: runtime and tensor-network hardness.

2. Present the general toolkit:
   - Partial exact simulation of reduced instances.
   - Specialized simulators.
   - Structural and invariant checks.
   - Analytic and spectral verification.
   - Sub-block verification plus composition reasoning.
   - Classical shadows, marginals, and correlators.
   - Inverse-circuit or echo tests.

3. Give per-family approaches:

| Family | Main Checks | Confidence |
| --- | --- | --- |
| QFT, QPE, Shor | Closed-form QFT checks, QFT inverse echo, known-eigenphase QPE tests, reversible modular arithmetic basis tests | Tier 2, with Tier 1 arithmetic sub-blocks |
| Grover | Analytic success curve, oracle-in-isolation, diffusion-in-isolation | Tier 2 |
| Hamiltonian simulation | Trotter step vs exact exponential, conservation laws, symmetry, MPS where possible | Tier 1 or Tier 2 |
| VQE/QAOA | Structure, parameter binding, special angles, expectation spot checks | Machinery only |
| Arithmetic | Basis-state truth-table samples, inverse/uncompute, ancilla cleanup | Often Tier 1 |
| Clifford/stabilizer | Stabilizer generators, syndrome checks, logical operators | Tier 1 |
| Random sampling | XEB, patch/elided circuits, structural schedule checks | Tier 3 |
| IQP/boson sampling | Low-weight marginals and correlators, diagonal/commuting structure | Tier 3 |
| HHL | QPE, eigenvalue inversion, uncompute, small known matrix | Tier 2 |
| Quantum walks | Basis action, unitarity, spectral checks | Tier 2 |
| QML/data encoding | Encoding map, feature loading, zero-input and distinguishability checks | Machinery only |

4. End with confidence tiers:
   - Tier 1: near-full confidence from classically tractable structure.
   - Tier 2: strong design confidence from analytic and modular structure.
   - Tier 3: statistical or partial confidence only.

Important phrasing:

> The one thing I will never do is report a specific full-scale output distribution I cannot actually produce.

## Example 3: Tier-2 QFT Verification Walkthrough

User asks:

> Make or find a large circuit, run verification checks, and explain each step.

Source example:

- Circuit: 100-qubit Quantum Fourier Transform.
- Why it is a good demo:
  - `2^100` amplitudes makes statevector simulation impossible.
  - The circuit is generated by a parameterized pattern.
  - QFT has exact closed forms and algebraic identities.

Generator pattern:

```python
from qiskit import QuantumCircuit
from math import pi

def build_qft(n: int) -> QuantumCircuit:
    qc = QuantumCircuit(n, n)
    for j in range(n):
        qc.h(j)
        for k in range(j + 1, n):
            qc.cp(pi / 2 ** (k - j), j, k)
    for i in range(n // 2):
        qc.swap(i, n - 1 - i)
    qc.measure(range(n), range(n))
    return qc

qc = build_qft(100)
```

Verification battery from the source:

### Step 1: Resource Estimate

Observed in the example:

- 100 qubits.
- Depth 201.
- 5200 gates.
- `needs_cutting = true`.

Why this matters:

- A 100-qubit statevector has about `1.27e30` amplitudes.
- Direct simulation is impossible.
- The gate count matches QFT shape:
  - `n` Hadamards.
  - `n(n-1)/2` controlled phase gates.
  - `floor(n/2)` swaps.
  - `n` measurements.

What it proves:

- The full-size generator produced the expected QFT structure.

What it does not prove:

- It does not verify the 100-qubit output distribution.

### Step 2: Small Exact Closed-Form Check

Example:

- Run the same generator at `n=5`.
- Input: `|00000>`.
- Expected QFT output: uniform amplitudes, each `1/sqrt(32)`.
- Observed: all 32 real amplitudes were `0.1767766952966368`, imaginary parts `0.0`.

What it proves:

- The generator matches the analytic transform for a tractable case.

What it does not prove:

- No direct claim about the full 100-qubit state.

### Step 3: Phase-Sensitive Deterministic Identity

Example:

- Prepare uniform superposition on 10 qubits.
- Apply QFT.
- Expected result: `|0000000000>` with probability 1.
- Observed: `0000000000`, probability `1.000` over 2048 shots.

Why this matters:

- This exercises phase structure. Incorrect controlled-phase angles would prevent perfect refocusing.

What it proves:

- The controlled-phase ladder behaves correctly for the tested size.

### Step 4: Echo / Inverse Test

Example:

- Prepare nontrivial input on 14 qubits.
- Apply QFT.
- Apply inverse QFT.
- Expected: exact original bit pattern.
- Observed: `10010001000101`, probability `1.000` over 2048 shots.

Why 14 qubits:

- The source conversation states that an attempted 20-qubit check hit a plan limit, so it was reduced to 14.

What it proves:

- QFT and inverse QFT compose to identity at this size.
- Wiring, swaps, and phase rotations are consistent for this tested instance.

### Honest Confidence Statement

Use this conclusion pattern:

> This is Tier-2 verification. The 100-qubit circuit is verified by construction: the full-size structure matches the QFT specification, and the same generator passed independent semantic checks at tractable sizes. I have not directly observed the 100-qubit output distribution. Residual risks include bugs that only appear at large indices, tiny controlled rotations, truncation choices, or numerical underflow.

## Example 4: Tier-1 GHZ / Stabilizer Verification

User asks:

> Same procedure on a Tier-1 circuit.

Source status:

- The PDF starts this example but stops before the results.
- Do not invent missing result values when using the source as a transcript.

Circuit:

```python
from qiskit import QuantumCircuit

def build_ghz(n: int) -> QuantumCircuit:
    qc = QuantumCircuit(n, n)
    qc.h(0)
    for i in range(n - 1):
        qc.cx(i, i + 1)
    qc.measure(range(n), range(n))
    return qc

qc = build_ghz(500)
```

Verification concept:

- A GHZ state is `( |0>^n + |1>^n ) / sqrt(2)`.
- It is pinned down by stabilizer generators:
  - Global `X^n`.
  - Adjacent `Z_i Z_{i+1}` for every neighboring pair.

Checks the source planned:

1. Confirm scale.
2. Check `ZZ` parity stabilizers.
3. Check global `X^n` stabilizer.
4. Run echo/uncompute test.

How Nameko should complete this example in a future run:

- Use a stabilizer simulator, not statevector, for large `n`.
- Verify all adjacent `ZZ` stabilizers have expectation `+1`.
- Verify global `X^n` has expectation `+1`.
- Verify measurements in the Z basis only produce all-zero or all-one strings.
- Verify the inverse ladder returns `|0...0>`.
- Record whether verification was exact stabilizer verification or a smaller sampled demo.

Honest confidence statement:

> This is Tier-1 verification only if the stabilizer formalism actually ran on the target width or the target properties were checked symbolically. If the tool only simulated a 15-qubit demo because of platform limits, then Nameko must label it as a demonstration of the method, not exact verification of the 500-qubit target.

## Reusable Mini-Examples

### Oracle Isolation for Grover

Check:

- Apply the oracle to computational basis states.
- Confirm it flips phase only for marked states.

Good claim:

> The oracle marks the intended basis states in the tested predicate cases.

Limit:

> This does not prove the Grover skeleton solves the problem if the predicate itself is wrong.

### Arithmetic Basis-State Test

Check:

- For an adder, sample `(a, b)` pairs.
- Confirm output is `a + b mod 2^n`.
- Include carry and wraparound edge cases.
- Confirm ancillas uncompute to zero.

Good claim:

> This is strong functional evidence because reversible arithmetic maps basis states to basis states and does not require statevector simulation.

Limit:

> Random sampling is not exhaustive unless paired with structural proof or exhaustive bounded-domain testing.

### Variational Special-Angle Test

Check:

- Set all angles to zero or other analytically known values.
- Confirm expected reference behavior.
- Confirm all parameters are bound before execution.

Good claim:

> This verifies the ansatz machinery and parameter plumbing.

Limit:

> This does not prove the optimizer will find the ground state or that the ansatz is expressive enough.
