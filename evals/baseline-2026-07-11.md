## Result: 0/6 (report snapshot: `report-baseline-2026-07-11-deepseek-only.json`)

The number is honest but the headline hides the real movement — **the plan stage is
fixed**: 6/6 runs produced schema-valid plans (`plan.produced`), versus 100%
`plan_invalid` before structured decoding. Failures all moved downstream, to three
characterized causes:

| Cases | Failure | Root cause |
|---|---|---|
| bench-01, 10, 28 | `sandbox_failed` at simulate | Generated code uses removed Qiskit legacy APIs: `QuantumCircuit.qasm()` (gone since 1.0), `.c_if()` (gone in 2.x). Model writes Qiskit 0.x idioms; sandbox has 2.x. |
| bench-14, 18 | `generate_invalid` "no code found" | Empty completion from DeepSeek at the generate stage (likely 4096 max_tokens overflow on VQE/QAOA-scale code). |
| bench-03 | ran end-to-end; verifier `inconclusive`, export `unsupported`, not saved | No QASM emitted (same `.qasm()` root cause) → IR parse starved the verifier. Exactly the "inconclusive + export unsupported" mode the IR-on-demand directive targets. |

## Fix under test (branch `feature/generate-qiskit2-api`)

Qiskit 2.x API constraints in the generate prompt (`qiskit.qasm2.dumps`, AerSimulator +

## Re-run result: 0/6 headline, all Qiskit-2.x failures eliminated
(snapshot: `report-rerun-2026-07-11-deepseek-qiskit2.json`, branch
`feature/generate-qiskit2-api`, same corpus/config/invocation as above with
`--out evals/report-rerun-2026-07-11-deepseek-qiskit2.json`)

The fix did what it targeted — zero legacy-API sandbox failures remain; every case
moved to a shallower, characterized cause:

| Case | Before (dev @ 46b283e) | After (PR #20) | Remaining blocker |
|---|---|---|---|
| bench-01 Bell | `sandbox_failed` (`.qasm()`) | ran end-to-end, export **lossless** | verifier `inconclusive` (plan chose `statistical` — unimplemented headless) |
| bench-03 GHZ | inconclusive, export `unsupported` | ran end-to-end, export **lossless** | same `statistical` starvation |
| bench-10 QFT | `sandbox_failed` (`.qasm()`) | `sandbox_failed` — `result.get_statevector()` without `save_statevector()` | generate prompt lacks statevector-workflow guidance |
| bench-14 VQE | `generate_invalid` empty | still empty — **8192 output tokens, len=0 content** (reasoning burn, not truncation; proven by the new machine-safe error) | DeepSeek reasoning consumes the whole budget on VQE-scale tasks |
| bench-18 QAOA | `generate_invalid` empty | generates + runs; QASM in stdout but export `unsupported` "no circuit produced" | IR likely lacks `rzz`; plan chose `brute_force` but code emitted no `baseline_instance` |
| bench-28 honesty | `sandbox_failed` (`.c_if()`) | runs; QASM emitted only inside the JSON string | `qasm_parse` starved (no raw QASM on stdout); corpus expects verifier `fail` |

**New dominant blocker: verifier method starvation.** Plans pick methods
(`statistical`, `brute_force`, `exact`) the headless path skips honestly
(services/worker stage_handlers `_run_verification`), so `outcomes == []` →
`inconclusive` → nothing saved. Candidate fixes for the next PR, in leverage order:
(1) implement `statistical` verification over counts (data is already in the result);
(2) always run RETURN_CONTRACT + QASM_PARSE in addition to plan-chosen methods, not
only when the plan names none; (3) constrain the plan prompt's method menu to what
the engine implements. Separate tracks: bench-14 reasoning burn (try
non-reasoning generate model or higher cap), bench-10 statevector prompt rule,
IR `rzz` support.

Phase-2 gate: ≥60% on this corpus (then expand toward 30 cases).

## Statistical-verifier run: 1/6 — FIRST HEADLINE PASS
(snapshot: `report-statcheck-2026-07-11.json`, branch
`feature/verifier-statistical-counts` @ `10d9419` (pre-review-fix code; the
review fixes only tighten validation/bit-order and could not change these
outcomes — all counts here are integer Qiskit dicts and Bell is
bit-reversal-symmetric), same corpus/config/invocation with
`--out evals/report-statcheck-2026-07-11.json`)

**bench-01 Bell is the pipeline's first fully verified, saved artifact on a live
LLM run:** `statistical` PASS (TVD 0.0088 vs the direct-simulation ideal, 3 bins,
shot-noise threshold), return_contract PASS, qasm_parse PASS → verifier `pass`,
export lossless, artifact + version written. Verifier method starvation is dead:
every executed run now produces verification.result events and a real decision.

| Case | PR #20 re-run | This run | Attribution |
|---|---|---|---|
| bench-01 Bell | inconclusive (starved) | **PASS + saved** | the fix, working end-to-end |
| bench-03 GHZ | inconclusive, lossless | verifier **fail** (honest) | model emitted no QASM this sample → always-run qasm_parse FAILs with the reason (was: silent starvation). Generate-compliance tail, not a verifier gap |
| bench-10 QFT | sandbox_failed (statevector API) | ran end-to-end, verifier fail | statevector bug didn't recur this sample; failed only on missing QASM (same class as bench-03) |
| bench-14 VQE | reasoning burn (len=0) | unchanged | stable failure; non-reasoning-model experiment queued |
| bench-18 QAOA | ran, export unsupported | sandbox_failed (generated-code crash) | sample variance; upstream of verify |
| bench-28 honesty | inconclusive | plan_invalid ("no JSON object") | plan-stage flake — structured decoding returned non-JSON once; expected-fail case would now flip via missing-QASM→FAIL when the plan validates |

**New top repeat offender: QASM-emission compliance** (bench-03/10 this round) —
the generate prompt demands it, models skip it stochastically. Next-leverage fix
is deterministic, not prompt-side: have the simulate stage append a sandbox
epilogue that dumps `FINAL_CIRCUIT` QASM itself, so emission stops depending on
model compliance. Then the verifier fix converts those runs too.

Corpus-level LLM nondeterminism note: each eval run regenerates plans and code,
so single-case flips between runs are samples, not regressions; attribute by
failure class, not case identity.

## bench-14 non-reasoning-model experiment (snapshot: `report-bench14-flash-2026-07-11.json`)

Same invocation, one-case corpus, `MAJORANA_MODEL_GENERATE=deepseek-chat`:
generate produced **real code — 1,517 output tokens in 14.3 s** (v4-pro: 8,192
tokens / ~145 s / zero content, reproducible 3 runs). The run then failed at
simulate on a generated-code bug (json.dumps on a non-serializable — numpy —
value), i.e. the ordinary code-quality tail, two stages deeper than before.
DECISION: generate default flipped to `deepseek-chat` (models.py, this PR) and a
numpy-serialization rule added to the generate prompt. Reasoning models stay for
plan (structured judgment) pending their own measured experiment.
