## Result: 0/6 (report snapshot: `report-baseline-2026-07-11-deepseek-only.json`)

The number is honest but the headline hides the real movement — **the plan stage is
fixed**: 6/6 runs produced schema-valid plans (`plan.produced`), versus 100%
`plan_invalid` before structured decoding. Failures all moved downstream, to three
characterized causes:

| Cases | Failure | Root cause |
|---|---|---|
| bench-01, 10, 28 | `sandbox_failed` at simulate | Generated code uses removed Qiskit legacy APIs: `QuantumCircuit.qasm()` (gone since 1.0), `.c_if()` (gone in 2.x). Model writes Qiskit 0.x idioms; sandbox has 2.x. |
| bench-14, 18 | `generate_invalid` "no code found" | Empty completion from DeepSeek at the generate stage (likely 4096 max_tokens overflow on VQE/QAOA-scale code). |
| bench-03 | ran end-to-end; verifier `inconclusive`, export `unsupported`, not saved | No QASM emitted (same `.qasm()` root cause) → IR parse starved the verifier. Exactly the "inconclusive + export unsupported" mode the IR-on-demand directive targets. |
